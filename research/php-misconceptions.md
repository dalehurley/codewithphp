# PHP misconceptions research

This brief maps the claims behind the Code with PHP series to primary sources and examples. Research was checked on 20 November 2026. The April 2026 PHP Foundation feedback describes a gap between current PHP and its reputation. Developer discussions supply examples of the wording people use. Neither source measures the prevalence of an individual belief. [PHP Foundation community feedback](https://raw.githubusercontent.com/ThePHPF/talks/main/board-presentations/PHP%20Community%20Feedback%20Summary%20-%20April%202026.pdf) · [PHP myths discussion](https://www.reddit.com/r/PHP/comments/1m6c6s7/) · [Web development discussion](https://www.reddit.com/r/webdev/comments/1r2bhnj/why_do_people_hate_on_php_so_much/)

Eevee’s 2012 critique is a primary source for several historical objections: coercion, inconsistent APIs and mixed error conventions. The modern manual and migration notes establish which examples still behave that way. Treat the critique as a record of the PHP its author encountered. [Eevee’s original critique](https://eev.ee/blog/2012/04/09/php-a-fractal-of-bad-design/) · [PHP 8.0 incompatibilities](https://www.php.net/manual/en/migration80.incompatible.php)

## Editorial choices

The launch order starts with types, performance and code quality. Each episode starts from a claim someone can recognise, then offers a modern example and a limit that matters in practice. The dollar-sign joke gets a short episode that actually explains licensing and cost. The critique of PHP's APIs earns its own episode because current quirks and historical changes each deserve a concrete example.

Workplace demand, salaries and comparative hosting prices would need a market, time frame and comparable workload. The series focuses on release activity, software licensing and cost inputs that readers can verify for their own app.
